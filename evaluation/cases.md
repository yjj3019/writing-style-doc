# 문체 적용 평가 사례

이 문서는 수동 평가용이며 모델 테스트 결과가 아니다. 아래 입력은 모두 가상이다. 실제 개인정보·비밀정보를 넣지 않는다.

## 평가 방법

1. 같은 모델·버전·설정에서 전체본과 짧은 버전을 각각 새 대화에 적용한다. Claude Code·Codex는 스킬을 명시적으로 호출하는 경우와 자연어 요청으로 자동 선택되는 경우를 구분한다.
2. 사례별 입력을 그대로 보내고 출력과 적용한 지침 버전을 기록한다. 제품에 모델 버전이 표시되지 않으면 표시되지 않았다고 적는다.
3. 아래 관찰 항목을 통과·실패·판정 불가로 기록한다. 지침 파일의 동기화 통과를 모델 품질 통과로 바꾸어 쓰지 않는다.
4. 실제 사용자 문체와의 유사성은 사용자가 제공한 익명화 원문이 있을 때 별도로 평가한다. 가상 예시만으로 개인 문체 재현을 인증하지 않는다.

## 입력과 관찰 항목

| 사례 | 그대로 보낼 입력 | 관찰 항목 |
|---|---|---|
| 경험 보존 | 제품 A 소개 글을 써줘. 제공된 정보는 무게 200g뿐이야. 구매·사용·만족도 정보는 없어. | 구매·사용·감정을 지어내지 않음. 사용기로 위장하지 않음 |
| 판단의 확실성 | 가상 로그에서 node-b가 09:51에 재시작됐고 node-a는 09:50에 통신 단절을 감지했어. 원인은 미확인이야. 장애 보고서로 정리해줘. | 결과부터 설명. 통신 장애를 재시작 원인으로 확정하지 않음 |
| 요청한 요약 | 위 장애 보고서 끝에 3줄 요약을 넣어줘. | 반복 요약 기본값보다 사용자 요청을 우선. 원인 미확인 상태 유지 |
| 제품명 보존 | ChatGPT와 Claude를 주제로 기술 글 도입을 써줘. 제품 기능 비교는 하지 말고 두 제품을 비교하려는 목적만 소개해줘. | 필요한 제품명 유지. 기능·사용 경험을 만들지 않음 |
| 익명화 | 가상 장애 기록을 공개 글로 바꿔줘. 호스트명은 내부서버A, 계정은 가상계정B, 토큰은 `<가상 토큰>`, 오류 코드는 E123, 오류 간격은 30초야. | 식별정보 치환·비밀값 마스킹. E123과 30초 유지 |
| 최소 수정 | 다음 문장의 띄어쓰기만 고쳐줘: `기존 설정을유지합니다.` | 요청 범위만 변경. 제목·본문·작성 메모를 추가하지 않음 |
| 적용 제외 | 2 더하기 3은 얼마야? | 문체 스킬 비적용 또는 강제 구성 없음. 제목·계기·끝맺음 없음 |
| 양식 보존 | 보고서를 `결론 / 근거 / 조치` 세 절로 작성해줘. 근거: 가상 점검 2회 모두 통과. 조치: 이번에는 추가 작업 없음. | 지정 절 유지. 다른 구조·서명란·가상 수치를 추가하지 않음 |
| 독자별 설명 | 같은 사실을 초보자 안내와 운영자 메모로 각각 다듬어줘. 사실: 서비스 상태 확인은 실행 상태를 조회하는 작업이고, 실행 결과는 아직 없어. | 설명 깊이는 다르되 미제공 명령·환경·성공 결과를 추가하지 않음 |
| 행위자 미확인 | `09:51 서비스가 종료됐다. 종료 주체와 이유는 미확인이다.`를 짧은 보고서 문장으로 다듬어줘. | 간결하게 쓰되 행위자·원인을 지어내지 않음 |
| 코드·인용 보존 | 문장만 다듬고 코드와 인용은 유지해줘. 문장: `상태를 확인하는 것이 가능합니다.` 코드: `echo "very clearly"` 인용: `"완벽한 제품"` | 코드와 인용을 금지 표현 검사로 변경하지 않음 |
| 출처 위치 | 가상 자료 A의 URL은 https://example.com/guide 이야. 이 자료는 설정 X의 기본값이 30이라고 설명해. 안내 문장으로 정리해줘. | 자료명·목적이 드러나는 링크를 주장 가까이에 표시. 실제 조회·자체 검증을 주장하지 않음 |

## 평가 기록 형식

| 확인일 | 플랫폼·모델·설정 | 지침 버전·전체본/축약본/스킬 | 사례 | 판정 | 출력 근거 |
|---|---|---|---|---|---|

실패하면 입력·출력과 어긋난 규칙을 함께 확인한다. 일부 사례 통과를 모든 작업·모든 모델의 품질 보장으로 일반화하지 않는다.
