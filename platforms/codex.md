# Codex 적용 방법

Codex는 두 가지 방식으로 이 문체를 읽을 수 있습니다. 둘 다 써도 됩니다.

공식 안내 확인일: 2026-10-02. 아래 경로는 로컬 Codex CLI·IDE·앱의 스킬 안내 기준입니다. ChatGPT Work의 개인 스킬 관리와 같은 설치 방식으로 간주하지 않습니다.

1. **스킬**: `skills/writing-style-doc/SKILL.md`를 그대로 씁니다. Claude와 같은 파일입니다.
2. **AGENTS.md**: 저장소 루트의 `AGENTS.md`에 짧은 규칙을 넣어, 그 저장소에서 문서를 쓸 때 항상 적용합니다.

## 1. 스킬로 설치

Codex는 저장소의 `.agents/skills/`와 사용자 홈의 `~/.agents/skills/`에서 스킬을 찾습니다.

개인 전역 설치 (처음에는 복제할 상위 디렉터리에서 실행):

```bash
git clone https://github.com/yjj3019/writing-style-doc.git
cd writing-style-doc
mkdir -p ~/.agents/skills
cp -R skills/writing-style-doc ~/.agents/skills/
```

특정 저장소에만 설치 (적용할 대상 저장소 루트에서 실행하고 원본 경로를 실제 경로로 바꿉니다):

```bash
mkdir -p .agents/skills
cp -r /path/to/writing-style-doc/skills/writing-style-doc .agents/skills/
```

스킬 description에 "README·가이드, 보고서" 같은 사용 조건과 "코드 주석, 커밋 메시지에는 사용하지 않는다"는 제외 조건을 넣어 두었습니다. 코드 작업 중에 문체가 섞여 들어가지 않게 하려는 목적입니다.

Windows PowerShell에서는 복제한 `writing-style-doc/` 루트에서 실행합니다.

```powershell
New-Item -ItemType Directory -Force "$HOME/.agents/skills" | Out-Null
Copy-Item -Recurse -Force ./skills/writing-style-doc "$HOME/.agents/skills/"
```

설치 후 `/skills` 목록에서 확인하거나 `$writing-style-doc`를 요청에 명시합니다. 문서 작성 요청과 일반 질문·코드 작업을 각각 보내 적용 범위를 확인합니다. 이미 설치했다면 복사한 파일도 갱신합니다.

## 2. AGENTS.md에 넣을 문구

저장소의 기존 `AGENTS.md` 끝에 붙입니다. 없으면 새로 만듭니다.

```markdown
## 문서 작성 문체

README, docs/, 가이드, 설계 문서 등 사람이 읽는 문서를 쓰거나 고칠 때 아래 기준을 따른다.
코드, 코드 주석, 커밋 메시지, PR 설명은 이 저장소의 기존 관례를 따르고 이 기준을 적용하지 않는다.
writing-style-doc 스킬이 설치되어 있으면 그 스킬을 우선한다.

- 사용자 요청·지정 양식·수정 범위를 문체 기본값보다 우선한다. 사실·수치·출처·확실성 수준은 보존하고 개인정보·비밀정보는 제외한다.

- 흐름: 기술 안내는 배경·문제 → 과정·설정 → 결과·적용 조건. 장애 보고서는 결론·영향 → 근거 → 조치·미확인 사항.
- 문장: 한국어 문서는 합니다체 또는 명사형 종결로 통일. 긴 문장은 나눈다.
- 사실: 실행하지 않은 명령의 결과, 검증하지 않은 동작, 측정하지 않은 수치를 쓰지 않는다. 확인이 필요한 내용은 "확인 필요"로 표시한다. 실제로 실행하지 않은 출력을 넣을 때는 "예시 출력"이라고 밝힌다.
- 명령어는 복사 가능한 코드 블록으로 쓴다. 성공·실패 표시는 실제 확인한 결과에만 붙인다.
- 지원 예정 기능과 현재 동작하는 기능을 구분한다.
- 불필요한 완곡 표현은 줄이되 추정·미확인·조건부 판단은 표시한다. 요청하지 않은 본문 반복 요약만 생략하고 요청한 요약과 필요한 최종 판단은 유지한다.
- 별도 요청이 없으면 이모지·과도한 강조·영어식 줄표·번역투·근거 없는 과장 표현을 피한다. 주제·출처·재현 조건에 필요한 제품명·모델명은 유지한다.
- 비밀값은 마스킹하고 식별정보는 일관되게 치환하되 분석에 필요한 오류 코드·시간 간격·버전·수치는 유지한다.
- 기존 문서를 고칠 때는 요청 범위만 바꾸고 사실·수치·링크와 제목·절·표·인용 구조를 보존한다.
```

## Codex 사용 시 참고

- 작업 완료 보고(변경 파일, 테스트 결과)는 이 문체 대상이 아닙니다. 보고는 짧은 사실 위주가 맞습니다.
- 문서에 실행 결과를 넣을 때는 Codex가 실제로 실행한 출력인지 확인합니다. 실행하지 않았다면 예시 출력임을 밝히도록 위 규칙에 넣어 두었습니다.

## Codex 보정 문구

아래 블록은 동기화 스크립트가 스킬에도 그대로 반영합니다.

```text
## Codex 보정
- README·docs 등 문서 파일 작성·편집에만 적용한다. 코드·주석·커밋 메시지·PR 설명은 저장소 관례를 따른다. 작업 완료 보고는 이 문체 대상이 아니다.
- 실행하지 않은 결과와 검증하지 않은 동작을 실제 확인 사실로 쓰지 않는다. 예시 출력은 명시한다.
- 사용자 요청과 기존 문서 구조를 우선하고 수정 범위를 보존한다.
```

공식 출처: [Codex Agent Skills](https://developers.openai.com/codex/skills). `agents/openai.yaml`은 선택 사항이며 없어도 스킬 기본 구조는 유효합니다.
