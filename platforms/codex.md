# Codex 적용 방법

Codex는 두 가지 방식으로 이 문체를 읽을 수 있습니다. 둘 다 써도 됩니다.

1. **스킬**: `skills/writing-style-doc/SKILL.md`를 그대로 씁니다. Claude와 같은 파일입니다.
2. **AGENTS.md**: 저장소 루트의 `AGENTS.md`에 짧은 규칙을 넣어, 그 저장소에서 문서를 쓸 때 항상 적용합니다.

## 1. 스킬로 설치

Codex는 저장소의 `.agents/skills/`와 사용자 홈의 `~/.agents/skills/`에서 스킬을 찾습니다.

개인 전역 설치:

```bash
git clone https://github.com/yjj3019/writing-style-doc.git
mkdir -p ~/.agents/skills
cp -r writing-style-doc/skills/writing-style-doc ~/.agents/skills/
```

특정 저장소에만 설치:

```bash
mkdir -p .agents/skills
cp -r /path/to/writing-style-doc/skills/writing-style-doc .agents/skills/
```

스킬 description에 "README·가이드, 보고서" 같은 사용 조건과 "코드 주석, 커밋 메시지에는 사용하지 않는다"는 제외 조건을 넣어 두었습니다. 코드 작업 중에 문체가 섞여 들어가지 않게 하려는 목적입니다.

## 2. AGENTS.md에 넣을 문구

저장소의 기존 `AGENTS.md` 끝에 붙입니다. 없으면 새로 만듭니다.

```markdown
## 문서 작성 문체

README, docs/, 가이드, 설계 문서 등 사람이 읽는 문서를 쓰거나 고칠 때 아래 기준을 따른다.
코드, 코드 주석, 커밋 메시지, PR 설명은 이 저장소의 기존 관례를 따르고 이 기준을 적용하지 않는다.
writing-style-doc 스킬이 설치되어 있으면 그 스킬을 우선한다.

- 흐름: 배경·문제 → 해결 과정 → 설정·명령어 → 확인 결과 → 주의점·적용 조건
- 문장: 한국어 문서는 합니다체 또는 명사형 종결로 통일. 긴 문장은 나눈다.
- 사실: 실행하지 않은 명령의 결과, 검증하지 않은 동작, 측정하지 않은 수치를 쓰지 않는다. 확인이 필요한 내용은 "확인 필요"로 표시한다. 실제로 실행하지 않은 출력을 넣을 때는 "예시 출력"이라고 밝힌다.
- 명령어는 복사 가능한 코드 블록으로 쓴다. 성공·실패 표시는 실제 확인한 결과에만 붙인다.
- 지원 예정 기능과 현재 동작하는 기능을 구분한다.
- 금지: 이모지 소제목, 근거 없는 "강력한/혁신적인/완벽한", "~것으로 보입니다" 연속, 끝 요약 단락, 영어식 줄표(—), 번역투("~를 통해", "~에 있어서").
- 기존 문서를 고칠 때는 요청 범위만 바꾸고 사실·수치·링크를 보존한다.
```

## Codex 사용 시 참고

- 작업 완료 보고(변경 파일, 테스트 결과)는 이 문체 대상이 아닙니다. 보고는 짧은 사실 위주가 맞습니다.
- 문서에 실행 결과를 넣을 때는 Codex가 실제로 실행한 출력인지 확인합니다. 실행하지 않았다면 예시 출력임을 밝히도록 위 규칙에 넣어 두었습니다.
